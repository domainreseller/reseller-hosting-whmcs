# 41 BLOCKER/HIGH findings and their resolutions (judge panel output)

1. CONTRACT-BLOCKER `_ConfigOptions` has no Operation and dies in the universal Kernel. RESOLVED: two dispatch paths. `Kernel::dispatchPure()` handles MetaData, ConfigOptions, ClientAreaAllowedFunctions, ClientAreaCustomButtonArray, AdminCustomButtonArray and LoginLink with no Bootstrap, no DB, no PanelResolver. `Registry::$entries` is the single table every rhpanel_* global must appear in, asserted by reflection in `tests/Contract/EntrySurfaceTest.php`.

2. CONTRACT-BLOCKER Ten reserved ordinals all named `(reserved)` collapse into one PHP array element (FriendlyName is the outer key), silently destroying the append-only guarantee — and OrdinalLock's `array_keys()` hash cannot see it. RESOLVED: emit only 7 ordinals, zero tombstones. Trailing ordinals are simply absent; appending later lands on ordinal 8 naturally. OrdinalLock now asserts `count() === 7` plus a per-producttype ordered-key hash, iterating producttype x isAddon x whmcsVersion.

3. MAINTAINABILITY-BLOCKER The ordinal budget was 100% allocated (14 used + 10 reserved = 24) with a third panel explicitly promised. RESOLVED: rebudgeted to 7 real ordinals (cpanel_package, plesk_plan, disk_mb, bw_mb, dedicated_ip, login_target, advanced). Six cPanel-only counters and Plesk add-on plans moved into the advanced textarea. 8-17 reserved for v2 reseller, 18-24 for a third panel.

4. MAINTAINABILITY-BLOCKER Two DDL owners, no migration runner, DDL swallowed on the hot path. RESOLVED: `Persist\Schema` is the sole owner; `mod_rhpanel_meta.schema_version` + an ordered `Migrations::$list`; DDL runs only from TestConnection and an explicit admin upgrade action under a non-blocking GET_LOCK; the hot path does one memoised SELECT and fails closed with RHP-1002 naming the repair action; a DDL permission failure prints the exact statement.

5. FAILURE-BLOCKER An empty Plesk `<filter/>` means ALL objects; combined with an unconditional `customer.del` a single missing link row is a reseller-wide wipe. RESOLVED: `Wire\Selector::of()` throws on any empty value; RequestSpec requires >=1 Selector for set/del/filtered-get; destructive Plesk verbs accept BY_ID/BY_GUID only (names are never mutation targets); the serialiser throws on a childless filter block; golden guard #4 forbids an empty filter in any set/del golden; behaviour test asserts zero packets sent on a wiped link row.

6. FAILURE-BLOCKER Create is not idempotent or resumable but the WHMCS module queue retries it, producing permanently wedged services. RESOLVED: get-then-add plan — `customer.get` by external-id and `webspace.get` by name always run; `customer.add`/`webspace.add` carry `shouldRun = !$bag->has(id)`; `link.upsert` preserves already-absorbed ids; an 'object already exists' on webspace.add is treated as already-provisioned after an owner check. Behaviour test: kill after customer.add, re-run, assert exactly one of each and 'success'.

7. FAILURE-BLOCKER The compensator stack unwinds on ANY throwable, so a response-parsing change deletes a successfully provisioned account; and the failing step's own compensator was never pushed. RESOLVED: `CommitCertainty` (NOT_COMMITTED / UNKNOWN / COMMITTED). The compensator is pushed as soon as any response returns, before parsing. Compensation runs only on NOT_COMMITTED. On UNKNOWN nothing destructive happens: `pending_sync += verify`, a repair event naming the object, and a PartialFailure message.

8. FAILURE-BLOCKER `<customer><set_password>` is not a Plesk XML-API operator, and the compensator set the FTP password to a random value nobody held. RESOLVED: the operator is `<customer><set>` with `<values><gen_info><passwd>` (on the live-panel gate with golden packets per dialect). Order reversed to panel-login-first, FTP-second; a failed FTP step returns 'success' plus `pending_sync=password` plus a resync action. The revert-to-random branch is deleted outright.

9. CONTRACT-HIGH The Loader contract is exception-driven and the catch-all Kernel makes it unreachable; the design also used a non-InvalidConfiguration class and a static `Server::getServerParams()`. RESOLVED: `Config\OptionLoader` bypasses the Kernel with its own catch(\Throwable); returns a flat escaped string=>string map; throws `WHMCS\Exception\Module\InvalidConfiguration` behind `class_exists` with a plain-Exception fallback; rebuilds empty $params via an INSTANCE `new \WHMCS\Module\Server(); ->load(); ->getServerParams()`; messages are attribute-escaped and redacted; wrong-panel returns array() rather than throwing.

10. CONTRACT-HIGH `DefaultSSLPort => 2087` makes locked-decision-13's Plesk port fallback permanently unreachable, because core backfills `serverport` from MetaData when the field is blank. RESOLVED: both port keys omitted from MetaData; `resolved_port` (the port the probe actually succeeded on) takes precedence; the probe tries per-panel candidate ports regardless of the configured value and reports a mismatch explicitly without silently rewriting the row; `AutoPopulateServerConfig` offers the correct port in the wizard.

11. CONTRACT-HIGH TestConnection specified two incompatible ways (multi-line string vs array); both core call sites do an unguarded `array_key_exists()` which is a PHP 8 TypeError on a string. RESOLVED: TestConnection is `ArrayReporter` only — `['success'=>true]` / `['error'=>string]`. The entire diagnostic report goes to `mod_rhpanel_servers.warnings`, `mod_rhpanel_events`, the server badge and logActivity. Warnings are never smuggled into `error`.

12. CONTRACT-HIGH + MAINTAINABILITY-HIGH No audience awareness: adminMessage (server names, panel versions, plan names, panel text) reaches customers through the client-area custom functions. RESOLVED: audience is an explicit `dispatch()` argument; ClassifiedError carries adminMessage/clientMessage; `AudienceLeakTest` invokes every client-audience entry against every failure persona and asserts none of {hostname, ip, version, plan name, RHP- code} appears.

13. MAINTAINABILITY-HIGH The reporter was chosen from the Operation object, which is null for any failure before the operation is constructed, returning a string from array-contract functions. RESOLVED: `Registry::reporterFor($entryName)` is a static name=>reporter table resolved BEFORE Bootstrap and before the registry lookup; the reporter's own `render()` is wrapped in a second try/catch with a hardcoded `lastResort($ref)` that touches no DB and no Lang file.

14. MAINTAINABILITY-HIGH Reserved tombstones would render as ten editable text fields that admins type into and v2 reads as reseller settings. RESOLVED: not emitted at all (same fix as the ordinal blocker).

15. MAINTAINABILITY-HIGH 17 Operations + 24 Strategies as class-per-table-row contradicting the design's own thesis. RESOLVED: declared `Registry::$operations` table + generic `Plan\SpecStep` driven by a `StepSpec`; real classes only for the six multi-step/conditional Plesk plans and the two usage strategies. ~133 files -> ~60. Exception hierarchy trimmed 12 -> 8 with `PanelErrorException::kind()` constants.

16. MAINTAINABILITY-HIGH Advanced-key validation was claimed for a `PreModuleCreate` hook that fires at provisioning, not product save (and hooks.php is dead until a product using the module is saved). RESOLVED: validation runs in `AdvancedOptions::parse()` at every ContextFactory build, plus a TestConnection product lint that checks every product in the server's groups (unknown keys, blank plan ordinal per panel present, Dedicated IP vs reseller Plesk, catalogue diff). hooks.php is advisory only, each body try/catch-swallowed. The false claim is removed from the docs.

17. MAINTAINABILITY-HIGH `debugContext` reached only `logModuleCall`, a no-op unless ModuleDebugMode is on, making RHP-9000 unactionable. RESOLVED: `mod_rhpanel_events` written unconditionally (rolling 2,000-row cap), indexed by the 8-hex ref that appears in every admin message, carrying code, step id, dialect, redacted detail, module/WHMCS/PHP/ionCube versions; surfaced on the server badge and the service admin tab.

18. MAINTAINABILITY-HIGH Loader/SimpleMode availability on WHMCS 7.8 is unverified but gates a locked v1 headline feature. RESOLVED as a process fix: it is a day-one verification spike (see decisionsNeedingHuman); the module feature-detects and appends an explicit Description note when unsupported, TestConnection prints the resolvable plan list on both versions, and the limitation is stated in INSTALL.md and on the sales page.

19. MAINTAINABILITY-HIGH `Kernel::runLoader` referenced `WHMCS\Exception\Module\InvalidConfiguration` with no feature detection, violating locked decision 4. RESOLVED: `class_exists` guard plus a `Support\Compat` helper centralising every version-variant WHMCS class/function reference, tested against both the 7.8-shaped and 8.x-shaped bootstrap stubs.

20. MAINTAINABILITY-HIGH No licensing seam in a product that is to be sold. RESOLVED: `Support\Licence::assert()` called from Bootstrap with a signed grace token in `mod_rhpanel_meta`; fails OPEN inside a 14-day grace and closed after; Terminate, Suspend, UsageUpdate, TestConnection, SSO and ClientArea always proceed regardless of licence state; only Create and ChangePackage are gated.

21. MAINTAINABILITY-HIGH No encode manifest, no plaintext-lang rule, tests and real captured fixtures shipping in the artifact. RESOLVED: `build/manifest.txt` + a release test that unzips the artifact and asserts lang/ and templates/ are readable source and nothing under tests/ or build/ is present; per-PHP-minor encode matrix with an encoded smoke test per target.

22. FAILURE-HIGH Unconditional `customer.del` on terminate deletes objects we do not own and cascades to sibling subscriptions. RESOLVED: read-first ordering (customer.get by external-id -> webspace.get by owner-id -> webspace.del by guid -> customer.del), with customer.del gated on ALL of: owner carries OUR external-id, owner has exactly one webspace, `owner_shared=0`, and dialect >= 1.6.6.0 so external-id exists at all. Otherwise webspace-only plus a warning event. NOT_FOUND on terminate returns success.

23. FAILURE-HIGH Unsuspend cleared the bit implied by the CURRENT identity, permanently stranding services after a credential swap, and never verified the result. RESOLVED: clear `mod_rhpanel_accounts.our_status_bit` recorded at suspend time; compute the residual before writing and refuse the write entirely when it contains bits outside our authority; re-read and assert the observed status after any successful write, on both the customer and the webspace object; `force` is admin-console-only, never an advanced-options key.

24. FAILURE-HIGH `ByteParser` was unit-agnostic, so a bare `'512'` MB disk limit became 512 bytes -> 0 MB -> 'unlimited'. RESOLVED: `parse($value, $requiredUnit)` with no unit-less call site; the '0 means unlimited' rule scoped to the cPanel disklimit field only; non-zero inputs floored at 1 MB; Quota rejects negatives and >2^50; float return so 32-bit builds do not TypeError in intdiv.

25. FAILURE-HIGH usage-null and limit-null shared one sentinel, so a missing `resource-usage` node zeroed customers' meters. RESOLVED: three states — Quota value / Quota::unlimited() / null-means-unreported. Null columns are omitted from the UPDATE, preserving the last good value, and the unknown count is reported through UsageReporter, `last_usage_error` and the badge.

26. FAILURE-HIGH UsageUpdate OOMs or times out at scale, and a PHP memory fatal is not catchable by catch(\Throwable), killing the whole cron. RESOLVED: cursor paging with a per-pass cap, a response body size cap with ProtocolException above it, a `memory_get_usage()` headroom check before decode, a wall-clock deadline whose truncated rows are SKIPPED not missed, chunked Plesk filters with per-result status mapping, batched writes, bulk reads excluded from the retry whitelist, and a 3-consecutive-miss rule before `orphan_since`.

27. FAILURE-HIGH A blank plan ordinal for the resolved panel produced an unfiltered `service-plan.get` and switched customers onto an arbitrary plan. RESOLVED: `PackageSelector` throws before any panel I/O when the ordinal for the resolved panel is blank; `PleskPackageResolve::absorb()` asserts exactly one result AND an exact name match; the same check is applied on the ChangePackage path, which previously had no guard at all.

28. FAILURE-HIGH cPanel package matching preferred the exact (root-owned) name over the reseller's prefixed one. RESOLVED: identity-aware candidate order (prefix first when identity_kind is reseller); the presence of BOTH forms is an explicit ambiguity error naming `cpanel.pkgprefix=force|never`; de-prefixing never collides in the dropdown; `strcasecmp` replaced with `mb_strtolower(..., 'UTF-8')` to avoid the tr_TR I/ı trap.

29. FAILURE-HIGH Following redirects with a custom KEY:/Authorization header leaks the reseller token to the redirect host, and CURLOPT_RESOLVE does not cover the redirect target. RESOLVED: `CURLOPT_FOLLOWLOCATION = false` on every API call; any 3xx is a ProtocolException naming the Location header; a `redirect-to-elsewhere` persona asserts the token appears in zero requests to that host.

30. FAILURE-HIGH SecretVault guessed wire encodings, dropped short secrets (logging them in cleartext), and missed the cPanel session URL. RESOLVED: redaction moved to the serialisation boundary via a `Secret` value object and placeholder tokens, so the loggable stream never contained the value in any encoding. SecretVault remains as a second layer for response-discovered values, derives its XML form from the SAME escape helper PacketBuilder uses, adds the whole query string of any URL in a response, and SUPPRESSES the body entirely rather than dropping a short secret.

31. FAILURE-HIGH Verbatim panel error text flowed into adminMessage and logActivity, neither redacted nor debug-gated. RESOLVED: adminMessage is built from lang/ keyed on the mapped code plus the numeric panel code; verbatim errtext goes only to the (redacted) events table; every outbound string including logActivity passes through SecretVault::redact(); a lint rule forbids constructing an exception message from an errtext-derived variable; traces are built from getTrace() with args dropped, never getTraceAsString().

32. FAILURE-HIGH Writing `probe_status='pending'` at probe start destroyed the cache-hit condition, causing a thundering herd that can trigger cPHulk lockout, and a transient failure took a known-good server offline. RESOLVED: non-blocking `GET_LOCK('rhpanel.probe.{id}', 0)`; losers serve the existing row; probe_status is never written at start; a failed probe never mutates panel_type or identity_kind; a differing successful probe sets `conflict` requiring explicit admin acknowledgement rather than silently switching drivers.

33. FAILURE-HIGH Plesk cannot honour per-service disk/BW overrides on a plan-bound subscription and Dedicated IP is inert under reseller credentials, so identical products silently yield different entitlements. RESOLVED: Dedicated IP + non-admin Plesk identity is a hard ConfigurationException at create (we do not provision); disk/BW overrides are written then immediately re-read and asserted, throwing if they did not stick; TestConnection ships a catalogue diff comparing every reachable product's configured limits against the panel plan's actual limits.

34. FAILURE-HIGH `InstallToken` had no defined storage or clone detection, so a staging clone could delete production Plesk customers. RESOLVED: stored in `mod_rhpanel_meta` alongside the SystemURL at generation time; a SystemURL mismatch makes all destructive operations refuse until acknowledged; every probe samples remote external-ids and TestConnection reports when another install's token is present on the same panel.

35. FAILURE-HIGH (cross-grafted from TDC) A server row repointed to a different panel routes existing services into the wrong driver's destructive operators. RESOLVED: `mod_rhpanel_accounts.panel_type` is a hard precondition asserted before every mutator; a mismatch throws with an actionable message, writes a repair event, and requires explicit admin re-binding. Combined with the `conflict` panel-type state this is closed from both directions.

36. CONTRACT-HIGH (cross-grafted from TDC) `_AdminLink` is unreachable whenever `_AdminSingleSignOn` exists, so the entire warning/diagnostic surface would never render. RESOLVED: the server badge moves to `_RenderRemoteMetaData` (called unconditionally in the same loop), `_GetRemoteMetaData` is implemented so the refresh control appears, `$params['remoteData']` is never dereferenced unchecked, and the Plesk admin auto-POST fallback button lives there too.

37. CONTRACT-HIGH (cross-grafted from TDC) `AutoGenerateUsernameAndPassword` undeclared and no tblhosting username write-back, breaking the advertised collision retry. RESOLVED: declared `true` explicitly; `LoginDeriver` validates against real panel constraints; any adjustment is written to BOTH `panel_login` and `tblhosting.username` through ServiceWriter (which is why `username` is on the write whitelist); a create conflict reconciles by read-back and adopts before it ever renames.

38. CONTRACT-MEDIUM-but-load-bearing `VoidReporter` returned 'success' unconditionally, discarding the only failure signal WHMCS offers for the usage cron. RESOLVED: `UsageReporter` returns the error string on failure so `ServerUsageUpdate` logs it, plus `last_usage_error` / `last_usage_success_at` and a red badge state after N days without success.

39. CONTRACT-MEDIUM `ClientAreaOperation` had no reporter and would have returned the literal 'success' into the Overview tab (or fallen through to a non-existent clientarea.tpl). RESOLVED: `ClientAreaReporter` always returns a template directive; only `tabOverviewModuleOutputTemplate` is used, never both slots, because returning the replacement template suppresses the module-output slot and would kill the Plesk auto-POST SSO fallback.

40. CONTRACT-MEDIUM `AutoPopulateServerConfig` unimplemented but called unconditionally after a successful TestConnection, with `implode()` on the result — a PHP 8 fatal in the Add Server wizard. RESOLVED: implemented, returning both `assignedIps` and `assignedips` as arrays and well-shaped-but-empty on failure.

41. CONTRACT-MEDIUM `_ClientAreaAllowedFunctions` never declared, making every client-area AJAX call silently inert; and no ownership assertion on custom functions. RESOLVED: declared with no parameters; every whitelisted function's first line is `ClientGuard::assert($params)` verifying session + tblhosting.userid ownership + status, enforced by a lint rule and a behaviour test with a mismatched userid.
