## WHMCS action → cPanel call vs Plesk call

Legend for mismatch severity: **[HARD]** needs a human design decision · **[UNIT]** numeric/encoding conversion · **[BROKEN]** currently broken in the bundled module · **[OK]** clean mapping.

| WHMCS action | cPanel / WHM API 1 | Plesk (XML-API operator) | Semantic mismatch |
|---|---|---|---|
| `CreateAccount` | `POST /json-api/createacct` — one call, one object. Fields: `username,password,domain,plan,contactemail,quota,bwlimit,savepkg=0,reseller=0,api.version=1` | **TWO calls, TWO objects**: `customer.add` (or `reseller.add`) → returns `customer/add/result/id`; then `webspace.add` with `gen_setup{name,owner-id,htype=vrt_hst,status}` + `vrt_hst{ftp_login,ftp_password}` + `plan-name` | **[HARD]** 1 WHMCS service = 1 cPanel account, but = 2 Plesk objects where the *customer is shared across services*. Plesk create is not idempotency-free: must look up an existing customer (via `mod_pleskaccounts` external-id map) before adding, or you duplicate customers. |
| `SuspendAccount` | `suspendacct` (`api.version=1,user,reason`) / `suspendreseller` | `webspace.set` → `gen_setup/status` = **16** (by admin) or **32** (by reseller); reseller product → `reseller.set` `gen-info/status` | **[HARD]+[BROKEN]** Plesk status is a **bitmask** whose correct value depends on *who you authenticate as*; a reseller generally cannot clear an admin-set (16) suspension. **Plesk has no reason field** — WHMCS `suspendreason` has nowhere to go. Bundled module emits `<domain><set>` which Plesk 18.0.80+ **rejects** (error 1014). |
| `UnsuspendAccount` | `unsuspendacct` / `unsuspendreseller` | Same `set` call with `status=0` — no dedicated unsuspend verb | **[BROKEN]** same `<domain>` breakage. Also: clearing status 0 wipes *all* suspension bits, including an admin bit a reseller shouldn't be able to clear. |
| `TerminateAccount` | `removeacct` (`user`, `keepdns`) / `terminatereseller` (requires a hardcoded url-encoded `verify` sentence) | `webspace.del` by domain, then **re-query owner's remaining webspaces**, and `customer.del` only if none remain | **[HARD]** Cascade decision has no cPanel analogue. `keepZone`→`keepdns` has no Plesk equivalent. Risk: a webspace not returned by the owner-id query causes collateral customer deletion. |
| `ChangePassword` | `passwd` (`user`,`pass`) — one identity, one call | **TWO calls**: `customer.set_password` (filtered by numeric **id**) AND `webspace.set` `ftp_password` (filtered by **domain**) | **[HARD]+[BROKEN]** Plesk has two distinct credentials per service. Bundled module silently no-ops the panel half when `accountInfo.login != params.username` (i.e. on a client's 2nd+ subscription). The webspace half is `<domain>`-rooted → broken on 18.0.80+. |
| `ChangePackage` | `changepackage` (`user`,`pkg` — **plain name**). Reseller → `setupreseller`/`unsetupreseller`+`setacls`+`setresellerlimits`. With Configurable Package Addon also `editquota`,`limitbw`,`modifyacct` | `service_plan_get_by_name` → extract `guid` → `webspace.switch-subscription` with **`plan-guid`**. Reseller → `switch_reseller_plan`. Then `processAddons` (`webspace.add-subscription`/`remove-subscription`) | **[HARD]** cPanel takes a name; Plesk needs a **name→GUID round-trip** (extra call, cacheable). Plesk add-on *plans* have no cPanel analogue. Bundled `switch_reseller_plan.tpl` is broken: emits `$externalId` but the caller passes `id`. |
| `UsageUpdate` | `listaccts` (disk as `'512M'` strings, already MB) + `showbw` (**bytes**) + `resellerstats` for resellers | `webspace.get` with dataset `resource-usage+limits+gen_info`, bulk-filtered by many `<name>` nodes. Reseller → `reseller.get_usage_by_login` | **[UNIT]** Three-way: cPanel disk = MB-with-suffix, cPanel bw = bytes, Plesk = bytes everywhere. No-limit sentinel differs: cPanel `'unlimited'` string vs Plesk `-1`. Bundled cPanel module does **no** conversion at all on the `resellerstats` path — already inconsistent today. Both receive **server params only** and must self-join to services. |
| `TestConnection` | `GET /json-api/version`. **Better: `myprivs`** — returns the caller's actual ACL set | `server.get_protos` (authenticated; doubles as version negotiation) or REST `GET /api/v2/server` | **[OK]** but both bundled versions are diagnostically useless. Recommend surfacing negotiated version + resolved identity (admin/reseller/customer) + missing-ACL naming. |
| `ServiceSingleSignOn` | `create_user_session` (`api.version=1,user,service=cpaneld\|whostmgrd\|webmaild`, optional `app`) → returns **a complete ready-to-use `data.url`** | `server.create_session` (login + **base64-encoded client IP**) → returns a **bare session id**, which must then be POSTed as `PLESKSESSID`/`PHPSESSID` to `/enterprise/rsession_init.php` | **[HARD]** Shapes do not line up. cPanel drops straight into WHMCS's `['success'=>true,'redirectTo'=>$url]`. **Plesk implements NO SSO function at all** — verified: grep for `SingleSignOn` under `modules/servers/plesk/` returns zero hits; it renders a raw HTML form in `ClientArea` instead. Also cPanel sessions are minted for an **account**, Plesk for a **login**. |
| `AdminSingleSignOn` | `create_user_session` with `serverusername` + `whostmgrd` | same `server.create_session` with the admin/reseller login | **[HARD]** Receives **server params only** — no service. Do not read `$params['username']` here. |
| `ListAccounts` | `listaccts` with `want=domain,user,plan,ip,unix_startdate,suspended,email,owner`; filter to `owner == serverusername` | `webspace.get` all + `customer_get_by_id` (falling back to `reseller_get_by_id` on literal `"Client does not exist"`) + `service_plan_get_by_guid` | **[UNIT]** Plesk maps **any non-zero** status bitmask → `SUSPENDED`. cPanel de-prefix in the bundled module is buggy: `explode("_",$plan)[1]` mangles any package name containing an underscore. |
| `GetUserCount` | `listaccts` with `want=user,owner` | `getResellerByLogin` + count customers by owner-login/owner-id, then resellers + their customers | **[OK]** conceptually; Plesk's is far more expensive. |
| `GetRemoteMetaData` | batch `version` + `systemloadavg` + `get_maximum_users` | `server.get` `<key/><stat/>`; load averages **divided by 100**; max accounts from license property `lim_cl` | **[UNIT]** load-average scaling differs. |
| ConfigOptions `Loader` (package list) | `listpkgs`, strip `<serverusername>_` prefix unless root | `service_plan_get` (names only) / `reseller_plan_get` | **[HARD]** cPanel **prefixes** reseller package names (`reseller_Gold`); Plesk **scopes** instead (names unchanged, but "you can use only service plans to which the XML API requester has access"). Same config field, different failure mode. Bundled Plesk reseller-plan Loader is broken — it uses returned **objects** as array keys. |
| `Renew` | not implemented by cPanel | not implemented by Plesk | **[OK]** omit; core converts to `'notsupported'`. |

### Auth surface, side by side

| | cPanel/WHM | Plesk |
|---|---|---|
| Endpoint | `{prefix}://{ip\|hostname}:{2087\|2086}/json-api/{cmd}` — **IP preferred over hostname** | `{prefix}://{hostname}:{8443\|8880}/enterprise/control/agent.php` — **hostname only, `serverip` never passed** |
| Auth header | `Authorization: WHM user:secret` (uppercase in WHMCS; vendor docs show lowercase `whm` — HTTP schemes are case-insensitive per RFC 7235). Same branch serves both legacy access hashes and modern API tokens. Falls back to `Basic base64(user:pass)`. | `HTTP_AUTH_LOGIN` + `HTTP_AUTH_PASSWD` headers. **No token support at all** in 7.8. Modern Plesk also accepts a `KEY:` header (XML-API) or `X-API-Key` (REST). |
| WHMCS field used for the secret | `serveraccesshash` = the API token | `serveraccesshash` = **the PORT NUMBER** (verified in 4 places) |
| TLS | `VERIFYPEER`/`VERIFYHOST` default to **0** (config flags default false) | `VERIFYHOST 0`, `VERIFYPEER false` **unconditionally hardcoded** |
| Timeout / retry | 400s default (30s for UsageUpdate); **no retries**, no connect timeout | 300s; no retries |
